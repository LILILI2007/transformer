# ModLingo 0.5.1：翻译失败与时间估算修复

## 怎么换到修复版

1. 关闭已经停止任务的旧软件窗口。
2. 运行 `D:\chatgpt工作区\ModLingo-v0.5.1-local\ModLingo\ModLingo.exe`。保留整个便携目录。
3. 选择同一游戏目录，重新配置并验证 API。密钥不会从旧窗口提取，验证仍可能计费。
4. 建议先勾选 2–3 个有文字的 mod 试译，观察失败数和名单，再扩大范围。不要重新使用 0.5.0 的可执行文件。

不用删除旧版本、缓存或备份。新旧版使用同一 `%LOCALAPPDATA%\ModLingo` 数据目录；已通过校验的成功候选继续按原文、上下文等匹配复用。未自动开始新的翻译或调用真实 API。此次插件程序没有变化，继续使用 ModLingo.Bridge 0.5.0。

## 已确定的问题

0.5.0 为合并片段生成的 `__ML_SPLIT_…` 标记，会在正常恢复后被同一个程序误认成“未知保护标记”。包含多个片段的有效译文因此被拒绝，并触发拆分重试。离线复现也会出现该错误，不能把它归咎于 API 服务。旧测试重点覆盖简单条目，遗漏了这个完整处理链路。

本次停止后的报告记录：运行约 1047 秒，共发送 265 次 HTTP 请求；新增成功保存 388 个片段，缓存/已有中文命中 52,804 个。停止时尚未安装本轮新增结果，成功候选已保存在 SQLite。旧报告中的模型“截断、过滤或工具调用”是合并错误信息；没有原始响应，不能追溯确定其具体状态。

## 修复内容

- 在恢复原始参数之前检查模型新增的非法标记；允许原文自身合法存在的标记。更换内部合并分隔符，数量和顺序校验继续保留。
- 合并及批次预算计入分隔符与输出 JSON 的开销，避免只统计原文字数。超出安全预算的单条文本不自动发送付费请求。
- 截断后缩小当前及后续批次；有效部分保留，仅处理失败部分。拒绝、过滤和工具调用不再当作普通格式错误反复重试；原始批次仍最多 8 次 HTTP 请求。
- 近期至少 4 个批次、最近最多 6 个批次中失败占比达到约 75% 时暂停后续调度，保留已返回结果。正在发送的请求仍可能计费。
- 明确显示成功、失败与缓存数量。“本轮剩余”排除准备耗时、扣除本轮已判定失败的条目；不会把失败当成译文成功。暂停时不继续显示估算。
- 将事件中明确的分支头、数字头像标记作为受保护参数。未知命令继续保留，未放开任意脚本改写。
- 新增逐请求诊断：`%LOCALAPPDATA%\ModLingo\reports\任务号.requests.jsonl`，记录协议、mod ID、批次、HTTP 状态、耗时、结束状态、请求预算和校验原因；不保存密钥、请求头、原文或译文正文。

## 验证证据

142 项自动回归：141 通过、1 项因本机创建符号链接权限跳过。新增回归覆盖真实形态的占位符、换行、性别分支、邮件、事件、嵌套分支、头像编号，以及标记伪造/丢失/重排拒绝、预算、自动暂停和预计时间。

真实准备记录的离线结构回归：116 个 mod、51,189 条记录、85,075 个片段，合并/模拟返回/校验/重建失败为 0。模拟输出只是用于检查结构，不能作为正式译文，也不证明模型质量或游戏内效果。原来 6 个文件异常 mod 没有在此回归中修复。

固定延迟压测：4 路相对串行吞吐 3.11 倍；万条简单文本及 2,000 条多片段文本通过，复跑均为 0 新请求。多片段负载共 100 次请求，没有额外格式重试。详细数据随包位于 reports。

没有使用真实密钥，没有替玩家发起试译。真实 API 的速度和兼容性仍需验证后的少量试译确认；二十分钟不作保证。全部 mod 的游戏内验收限制见 [0.5.0 基础指南](0.5.0测试指南.md)。
