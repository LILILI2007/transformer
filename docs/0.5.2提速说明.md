# ModLingo 0.5.2 本地测试版

## 怎么运行

退出旧版 ModLingo，打开 `ModLingo.exe`。保持原来的游戏目录，配置 API 并验证成功，点击“翻译并安装”。软件先扫描并复用缓存，弹出实际待译量，确认后开始付费翻译。默认 4 路并发，先选少量 mod 观察服务响应，再扩大范围。无需删除历史项目、译文、备份或 SQLite。

新旧版本共享 `%LOCALAPPDATA%\ModLingo` 缓存，请勿同时运行。新增完整字段记忆表是增量变更，旧缓存键保持兼容。新的匹配结果会在通过结构检查后复用；不能保证模型或配置改变后全部命中。插件仍为 0.5.0，无需仅为此次提速重装。

## 这次解决什么

- **缩批可以恢复**：每个 mod、每种文本长度分别维护批次。三次满批成功后逐步增长，最大 20 条。旧请求的成功反馈不会覆盖较新的缩批结果。派发时重新组成批次，避免提前切成一条后永远无法合并。
- **只合并安全重复**：同 mod、相同用途命名空间或相同资源中的完整长文本，原文和控制参数完全一致才考虑合并。短标签和未知用途不泛化；不同说话者隔离。已付费的部分缓存继续使用。已有玩家译文不同会阻止该原文自动复用，保留各自修改。
- **减少拆句损耗**：普通对话优先发送完整字段，模型能看到完整语境和保护参数。成功后拆回原有片段缓存；事件、附件、未知命令继续结构化处理，不把参数暴露成待译文字。
- **只补失败部分**：同一结构字段中有效片段立即保存，未翻译、空白或校验失败片段单独补试；所有拆分仍共享原批次 8 次 HTTP 预算。
- **先核对用量**：扫描阶段不请求翻译 API。确认框显示已可用量、重复合并量、唯一待译片段、实际待译字段和初始 HTTP 请求估算。估算不含重试、拆分、限流和动态缩批，不能据此计算最终账单。API 验证仍可能计费，保留原来的验证确认。
- **诊断更清楚**：缩批、回升、解码错误都包含批次和 mod 标识。HTTP 记录包含是否关闭思考以及服务返回的 reasoning_tokens（如有）；不记录思考正文、密钥、请求正文或模型原始响应。未捕获的工作异常生成暂停报告，保留已校验缓存，未确认工作列为待重试。

DeepSeek 新预设使用 `thinking: {type: disabled}`。其当前官方文档说明默认开启思考，可显式关闭：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。这不证明玩家过去的请求开启了思考。自定义配置与其他厂商按各自协议处理，不能把该参数任意发送给所有厂商。

## 已验证与限制

自动测试全部使用模拟接口或本地 HTTP 合约服务器，无真实密钥，不调用付费 API，不改写玩家游戏文件。使用用户保存的准备 JSONL 只做读取和模拟结构验证。

| 离线场景 | 结果 |
| --- | --- |
| 固定 0.1 秒响应，1,000 条、4 路对比串行 | 2.91 倍吞吐；并发峰值 4 |
| 10,000 条简单文本 | 500 次请求；复跑 0 请求 |
| 2,000 条多片段文本 | 100 次请求；复跑 0 请求 |
| 500 条，从每批 1 条开始、固定 0.005 秒响应 | 固定单条 500 次；自适应恢复 39 次，回升至 20 条 |
| 1,000 个字段，25 种相同用途完整长文本 | 去重为 25 个字段、2 次请求；不是玩家真实重复率 |
| 实际准备数据，116 个 mod | 52,642 条含片段记录、90,855 个结构片段通过模拟结构检查；52,007 条可走整字段路径 |

90,855 是结构片段数量，包括原有已翻译内容和标点片段，并不是待请求数。真实 mod 数量无法直接推算文本量；大型剧情包占比很高。之前的冗余审计发现重复候选，但安全用途隔离、已有缓存和玩家修改会进一步限制实际可合并数量，不能承诺把全部候选转化为费用节省。

153 项自动测试中 152 通过、1 项因 Windows 符号链接权限跳过。覆盖批次恢复和隔离、公平调度、缓存复用、玩家修改冲突、邮件附件保护、停止、限流、截断、请求预算、异常退出和五家主要 API 协议。详细数据在包内 `reports`。真实模型输出质量、服务速度和游戏内效果仍需玩家试译验收；不能承诺二十分钟完成整个库。DLL 采集范围和游戏生效边界沿用 0.5.0。
