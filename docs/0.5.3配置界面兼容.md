# 0.5.3：GMCM 配置名称、选项与插件完整性

## 玩家操作

退出旧版软件，运行本版本 `ModLingo.exe`。点击“安装采集插件”更新至 Bridge 0.5.1。用 SMAPI 启动并选择中文，打开 GMCM mod 配置列表及仍有英文的设置页，展开下拉框、悬停需要翻译的说明。退出游戏后，在桌面工具重新扫描、配置并验证 API、确认实际待译量，再翻译安装。下次启动加载新译文。

旧缓存、备份、`translations` 与 `captures.json` 均保留；已完成的有效文字继续复用。首次缺失文字必须采集和翻译，安装插件本身不会凭空生成中文。不要同时运行新旧软件，也不要在游戏运行时安装译文。

## 改动与安全边界

- GMCM 列表名称来自 `ModConfig.ModName`，不是普通 i18n。新适配器只替换这个 GMCM 显示属性。DLL 声明名称作为独立 `gmcm/mod-name` 文本单元，其他已注册名称由游戏采集。插件记录按 mod 身份/版本、上下文、原文哈希匹配。
- GMCM 下拉显示来自 `formatAllowedValue`/`FormatChoice`。适配注册接口和运行时显示 getter，解决部分格式文字在注册时已被缓存的问题。原始选项值、读写委托保持不变；只有 `allowedValues` 中的值才可采集，不处理自由输入框。包装器采用弱引用缓存。
- 安装插件译文时检查伴随程序，缺失或旧版时补齐/升级，保留玩家已有译文和采集文件。磁盘安装完整只代表程序在位，不能代替 SMAPI 加载验收。
- i18n JSON 文件异常继续报告、保留原文件，但不会连带阻塞独立 GMCM 采集或资源译文。无法解析的 i18n 原文件仍不写入。
- `$query` 条件头、`$action` 动作串和数字物品列表原样保护，只翻译已识别的人类可读片段。未知命令继续保留、报告，未放宽结构校验。

GMCM 接口依据：[官方 API 源码](https://github.com/spacechase0/StardewValleyMods/blob/develop/framework/GenericModConfigMenu/IGenericModConfigMenuApi.cs)。本机实测 GMCM 1.16.0、SMAPI 4.5.2、游戏 1.6.15。其他版本及自定义 UI 框架尚不能保证全面兼容。

## 验证

160 项自动测试：159 通过、1 项因符号链接权限跳过。新增回归覆盖名称单元去重、i18n 异常后继续采集、条件/动作保护（含动作后分支和引号参数）、数字物品列表、插件补齐与升级及译文保留、拒绝覆盖其他 mod。按新版解析器重读真实准备原文：116 个 mod、52,643 条含片段记录、90,848 个结构片段，离线模拟重建检查通过；片段数量不是待请求数量。

隔离游戏探针使用独立 Mods，只运行标题界面，不加载存档、不调用 API：GMCM 名称返回中文、下拉格式返回中文、原始配置值不变、任意输入不被采集；资源中文替换、DLL 绘制替换及三种采集来源同时验证。探针主动调用真实 GMCM 属性/格式委托，尚未证明玩家所有菜单的视觉排版和交互都已验收。详情见包内 `game-probe-0.5.3.json`。

纯图片中文字、未访问的动态界面及未知绘制框架仍有边界，不能宣称所有英文都能自动消失。
