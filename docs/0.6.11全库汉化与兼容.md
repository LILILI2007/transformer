# ModLingo 0.6.11 / Bridge 0.5.6

本版面向当前玩家的全库增量汉化，保留旧译文、缓存和备份。开发与验收不调用翻译 API；缺失译文由玩家在程序中启动补译。

## 使用

1. 退出游戏和 SMAPI，启动独立目录中的 `ModLingo.exe`。
2. 选择游戏目录，点击“安装采集插件”，将 Bridge 更新为 0.5.6。
3. 配置自己的 API 并验证。验证和随后启动的翻译都会真实请求服务商。
4. 默认只补缺失。已耗尽内容重试的条目不会自动重发；确实需要时再勾选“重试待处理（计费）”。
5. 查看结果名单。同名 JSON 提供逐条原因、覆盖分类、质量检查线索和运行时命中证据。
6. 以中文启动游戏。原生配置文字不再要求先逐页采集；其他动态界面仍需实际访问，退出后再扫描补译。

“可提取”“已生成译文”“已安装”和“已观察到生效”分别统计。未访问的动态界面、未加载的剧情和未知资源保持未验证。部分内容含英文的检查提示可能是正常专名，不能自动认定为错误。

## 变化

- 原样返回、专名和单条结构错误不再直接触发全库失败比例保护。连续四批无有效结果只暂停同一 mod、适配器及文本类型；跨多个 mod 的响应协议/结构异常仍可全局暂停。
- 每条内容只允许一次有策略变化的修复，所有拆分和 HTTP 重试仍共享八次上限。输出截断优先拆为较小批次；结构损坏的合并字段拆为独立片段。成功片段即时保存。
- 独立诊断表保存实质原因和翻译尝试次数，暂停状态不覆盖根因。未确认响应不能假定免费。
- Content Patcher 配置通过原生 `config.<字段>.name`、`.description`、`.values.<实际值>` 和 `config.section.<分组>.name` 汉化。只生成中文语言键，不改 ConfigSchema、config.json、字段 ID 或选项实际值。
- 相同 mod、完全相同允许值列表中的重复显示值复用翻译，避免矿车多个目的地槽重复收费。其他短标签不做跨语境合并。
- 对三个已知问题 mod 添加少量已核实的中文显示规则。mod 标题保留英文原名，已有玩家译文优先。
- Bridge 输出 GMCM 能力检测、会话标识和唯一文本命中；按原文、译文哈希与 mod 版本匹配，旧会话不能证明新译文已经生效。
- 扫描快照可指出具体变化文件；安装前拒绝多个 mod 共用输出目标。历史 East Scarp/RSV 错误未重现时保留未知原因。
- 单独记录等待确认时间。Windows 每次安装前通过原生进程枚举检查游戏，不再反复启动 tasklist。

## 验收边界

全库离线报告使用玩家 Mods 与 SQLite 的独立副本，零网络请求；它证明提取、缓存复用和副本安装，不代表首次冷缓存速度或全剧情完成。真实框架探针只进入标题界面，不打开存档。三个真实 CP mod 的探针读取其配置显示函数并检查原值，不能替代所有分辨率下的视觉布局验收。

选项序号不一致会列入人工核对并从合格记录数中扣除；已有文件不会因此被擅自删除。旧译文中的语义错误仍可能需要人工修改。未知来源、图片文字、重复安装和损坏 JSON 不通过放宽校验解决。

本地测试数据、玩家捕获及数据库不进入程序包。具体测试计数、逐 mod 覆盖及尚未完成项见交付目录的报告。
