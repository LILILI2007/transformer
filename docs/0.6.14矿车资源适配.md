# ModLingo 0.6.14 / Bridge 0.5.8

本版实现第一阶段的矿车资源适配与显示名称解析，保留既有 Python 引擎、SQLite 缓存和离线 Bridge 架构。

## 支持范围

- `Data/Minecarts` 的网络提示 `LockedMessage`、`ChooseDestinationMessage`、`BuyTicketMessage`，及目的地的 `DisplayName`、`BuyTicketMessage`。
- CP 的 `Entries`、`Fields`、静态 `TargetField` 与 JSON `Load`。真实目的地列表按 `Id` 定位，列表重排不改变翻译上下文；重复、缺失或动态 Id 不猜测。
- 原作者纯 i18n 引用、明确可见的字面名称、已有合格缓存及已匹配的 Bridge 字典译文。名称可由另一个已扫描的内容包提供，必须明确属于同一个目的地实体。
- 简单 `[LocalizedText Strings/...:Key]` 引用由中文游戏读取，保留原引用与解析结果哈希；桌面端核对路径、来源版本、语言与当前定义后复用。

目的地标识始终保留原样，中文写入配置显示语言键或 Bridge 显示字典。没有更改 `config.json`、`AllowValues`、目的地 Id、目标地图、坐标、价格、条件或自定义字段。

## 保守边界

- 自定义名称、玩家输入和未知动态表达式不发送给翻译模型，也不从任意运行时字符串猜测对应关系。
- 多个名称来源冲突、另一个网络使用相同 Id 但显示名称不同、删除定义或未知条件分支，保持待处理。
- 保留已有译文和玩家主动回退。来源文件在扫描后改变时，中止依赖这些名称的安装。
- 本版不会在新名称翻译完成后重新调度所有依赖选项；这是后续依赖调度工作的范围。
- 新 Bridge 需要访问相关游戏资源才能取得本地化观测；不存在的可选内容包、未观察到的引用不会凭空产生名称。

## 使用

1. 退出游戏，启动本版程序，在界面安装或更新采集插件至 0.5.8。
2. 正常进入游戏并访问矿车相关资源和配置界面，再退出并重新扫描。
3. 程序复用通过校验的名称；仍缺少原始名称或中文证据的标识继续列为待处理。

源代码测试和游戏框架探针均使用独立测试数据，不读取存档，不需要调用收费 API。当前版本的开发验证没有把测试译文写入玩家 Mods。

## 验收口径

显示位置覆盖率、唯一名称覆盖率和实际游戏显示命中应分别理解。一个可靠名称可能用于150个配置位置，不能把这些重复位置当成150个独立语义内容。

本版交付会包含回归结果、矿车资源标题探针和离线副本报告。资源替换、原配置保持与名称解析通过，不等同于全地图、存档剧情和全部条件分支完成验收。

2026-11-21 本地验证：306项回归，305通过、1跳过；真实框架标题探针验证矿车中文资源、原值及自定义字段保持、私有名称不采集、内置本地化解析。均未调用收费API，未打开存档。

当前固定副本离线复核为70,668/80,333条合格记录（87.97%）。相对前一版副本新增300个矿车配置显示位置，对应两个有原作者语言键证据的目的地；新增资源提取也增加了6条记录，因此分母不同。矿车仍有9,328条待处理，尚未达到95%。本轮没有把测试结果写回玩家Mods。
