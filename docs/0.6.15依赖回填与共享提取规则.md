# 0.6.15 依赖回填与共享提取规则

配套 Bridge 0.5.9。此版本完成两项架构改进，首个接入依赖图的业务是矿车目的地显示文字。

## 同轮回填

依赖关系为“原文/资源字段 → 目的地名称 → 配置菜单显示位置”。普通文字仍按原有并发、公平队列、有限重试和费用保护执行；内部目的地标识不提交给模型。

- 等待名称的字段记为 `waiting_dependency`，不会在规划阶段直接判定为翻译失败。
- 名称提供者的所有片段通过原有校验后，更新名称索引并回填等待中的显示文字，无需再次扫描或再次调用 API。
- 已有缓存、原作者中文及本轮新译文均可提供名称；结果不依赖模组扫描顺序。
- 已知条件/网络的名称定义必须一致；缺失、冲突、自定义名称和循环依赖继续保留原值。原作者/玩家要求的原文回退受保护。
- 不用旧的“直接翻译 ID”片段缓存或整字段记忆绕过名称证据。停止后的合格提供者译文仍在缓存，后续任务重建依赖并继续。
- 安装前复核名称提供者的来源文件，来源变化则阻止相关消费者安装。已有正常译文不因新依赖图被清空。

核心实现：`modlingo/dependencies.py`。`DependencyGraph` 保存任务边与状态，`NameDependencies` 接入矿车名称适配器，`Engine` 在有效译文返回后触发回填。新增其他依赖业务仍需对应的语义适配器，本版不猜测任意模组之间的隐含关系。

报告新增 `dependencies`：同轮回填字段数、未完成字段数、名称提供者字段数、依赖边数、刷新次数及待处理原因。规划报告单独列出依赖等待字段，避免把它们计入模型请求估算。等待信息不作为“已译”计入覆盖率。

## 两端共享资源规则

唯一规则源为 `modlingo/resource_rules.json`。Python 读取该文件；C# 在构建时将同一文件嵌入 Bridge DLL，不依赖用户另外复制规则文件。

该规则文件通过 `.gitattributes` 固定为 LF 换行，避免不同系统检出时改变字节指纹，确保与预编译 Bridge 中的规则一致。

共同规则包括支持的资源及精确/目录边界、通用显示字段、额外 Name 字段、矿车和世界地图的结构路径、按 Id 定位的列表位置、合法静态 Id、最大路径深度、已知语言范围以及 i18n/内置本地化引用的格式。未知相似资源名如 `Data/ObjectsExtension` 不再因为前缀相同而被视为已支持。

静态 CP 提取、Bridge 来源索引、游戏资源遍历，以及 Python 导入资源采集记录，均使用这套字段和路径判定。内部 Id、价格、条件、自定义元数据不会因为字段名接近显示字段而获得矿车或地图文本资格。

两端保留各自必要的工作：Python 拆分并重建剧情脚本，Bridge 读取游戏已解析的资源并执行替换；共享契约不代替游戏条件求值，也不代表静态原文与运行时结果必然逐条相同。

采集文件和任务报告记录规则版本及 SHA256。旧采集没有规则指纹时显示为未知，不伪称两端一致；导入仍按当前规则过滤。

`bridge/contract` 使用生产代码的 C# 规则解释器，不依赖游戏运行。测试以相同样例在 Python 和 C# 两端执行，并对照明确的正反例，覆盖资源名边界、路径大小写、重复/缺失 Id、动态引用、语言条件和规则字节指纹。

## 使用与验收边界

退出游戏，运行新程序并点击“安装采集插件”，将 Bridge 更新到 0.5.9；继续使用现有 API 配置和缓存即可。已有可确定名称的新译文会在同一轮回填；仍缺少运行时名称时，进入对应界面采集、退出后重新扫描。

本版开发测试使用模拟模型响应和隔离副本，不产生真实模型费用、不修改玩家实际 Mods、不加载存档。测试证据随本地交付报告提供；同轮回填正确性不等于译文语义质量、所有游戏界面验收或全库覆盖率已达到 95%。
