# ModLingo 0.4.0 预览版 · API 协议兼容性

第四次 GitHub 更新，重点增加厂商预设、协议适配与独立 HTTP 兼容性测试。

## API 支持名单

- 重点支持 DeepSeek、千问/百炼、Kimi、OpenAI、Claude。
- 扩展 Gemini 兼容接口、硅基流动、OpenRouter、Ollama、LM Studio。
- 共 12 个厂商/区域/协议预设及 1 个自定义入口；三种协议为 Chat Completions、OpenAI Responses、原生 Claude Messages。
- 千问北京/新加坡地址与密钥须对应，默认关闭思考；Claude 支持版本头、原生文本块和工作区；OpenAI Responses 与 Chat 独立处理。

完整地址、配置说明、兼容限制和官方依据见仓库 docs/API支持名单.md，便携包内 docs 文件夹也有该文件。

## 使用和改进

“配置 API”中先选厂商，填写控制台的模型 ID 和密钥，可调整最大输出 tokens、超时和适用模型的思考开关。切换厂商会清空密钥。两种工作台共用设置界面。

截断、拒绝、工具调用和只有思考过程的响应均拒绝写入译文；鉴权与错误正文脱敏；保留占位符、换行检查及限次重试，新增 Claude 529 重试。协议/参数错误 400 会停止后续批量请求。

## 验证边界

本地 90 项测试：89 项通过、1 项链接测试因权限跳过。12 个厂商预设均通过本机真实 HTTP 收发与结构检查，覆盖三协议、鉴权、思考参数、截断、重定向、重试和设置切换；这不是对真实商业云端的验收。

没有可用真实 API 凭据，本次未调用商业模型。各厂商真实鉴权、地区可用性、模型质量与费用仍待验收。源码新增自愿付费检查脚本 scripts/check_live_api.py；没有 --allow-paid 不发送请求，记录不含密钥或原始响应。

只支持非流式文本，不保证厂商所有模型、转发平台、专用云认证或必须流式的模型可用。便携程序仍为未签名预览版；游戏内效果与无 Python 玩家机器仍待验证。
