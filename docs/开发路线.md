## M2：真实试点（12–24 小时粗估）

- [ ] 选一个用户实际使用的模型服务，记录接口配置、返回结构、计费 usage。
- [ ] 取得允许本地测试的真实标准 i18n mod，覆盖已有中文、对话和更新场景。
- [ ] 在实际游戏、SMAPI、mod 版本组合上验证安装、回退与显示。
- [ ] 保存脱敏测试报告，不提交密钥、未授权 mod 资产或个人存档。

验收：至少完成一次真实“导入→翻译→复核→安装→更新补译”，记录真实结果和仍不支持的文本类型。无需假装覆盖所有 mod。

## M3：降低普通玩家门槛（20–40 小时粗估）

- [ ] 观察 5 名普通玩家试用，记录卡点和总完成时间。
- [ ] 实测对比现有工具；没有独立价值时转向贡献或复用现有项目。
- [ ] 根据真实 API 添加经过测试的供应商预设，保留高级自定义。
- [ ] 增加逐条重试、批量确认/回退，提升大文本列表性能。
- [ ] 增加滚动备份、异常关闭恢复和项目 schema 迁移测试。
- [ ] 提供受支持文本覆盖比例，避免用户把导出成功理解为全汉化。

验收：有可复现的用户操作与数据支撑；不以“功能更多”替代体验证据。

## M4：扩大兼容（30–60 小时起，按需拆分）

- [ ] 分文件 i18n 布局；保持文件映射、键冲突和安装路径规则。
- [ ] 对话语法 tokenizer/AST，先支持性别分支，再分批支持复杂命令。
- [ ] 多 mod 扫描与队列，翻译记忆保持 mod/语境隔离。
- [ ] 剧情上下文与人物用语配置，控制发送范围和长度。
- [ ] 在有充分样本后评估硬编码 Content Patcher 字段提取；单独成适配器。

验收：每新增一种语法都有代表性正反例、结构保持规则与游戏内验证。无真实需求时不优先兼容 DLL/XNB。

## M5：公开发布与维护（12–24 小时起）

- [ ] 干净 Windows 机器测试，无 Python 环境下启动、路径含中文、普通用户权限。
- [ ] 检查第三方许可文件完整性、程序架构、打包供应链与文件哈希。
- [ ] 评估代码签名与更新渠道；未签名构建如实说明。
- [ ] 用 GitHub Issues 收集脱敏问题，按导入、API、结构、更新、安装分类。
- [ ] 在真实试点通过后发布首个公开版本与兼容列表。
